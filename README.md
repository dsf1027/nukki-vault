# 누끼 보관함 (Nukki Vault)

사진을 찍고, 물건을 **1초 꾹 누르면** 누끼가 따지고, 그걸 **보관함 탭으로 끌어다 놓으면** 보관함에 **툭 떨어져** 쌓이는 웹앱(PWA)입니다. 빌드 과정과 서버가 없고, 사진과 보관 데이터는 모두 기기 안(IndexedDB)에만 저장됩니다.

## 사용법

1. **📷 카메라**에서 셔터를 누르거나 🖼로 앨범 사진을 고릅니다.
2. 사진 속 물건을 **1초 누르고 있으면** 링이 차오르며 누끼가 따집니다. 손을 떼지 않고 그대로 끌 수 있습니다.
3. 누끼를 **아래 '보관함' 탭**에 가져다 대면(약 0.35초) 보관함 화면으로 넘어갑니다. 손은 그대로 두세요.
4. 보관함에서 **손을 떼면** 물건이 바닥으로 떨어져 보관됩니다.
5. 보관된 물건은 서로 **겹칠 수 있고**, 끌어서 옮길 수 있으며(놓으면 다시 떨어집니다), **한 번 터치하면 맨 앞**으로 나옵니다. 투명한 부분은 터치가 통과해서 뒤의 물건이 선택됩니다.
6. 보관함에서 물건을 끌 때 위쪽에 나오는 **🗑**에 놓으면 삭제됩니다.

## 실행

```
python3 -m http.server 8080     # http://localhost:8080
```

카메라(`getUserMedia`)는 브라우저 보안 정책상 **HTTPS 또는 localhost**에서만 동작합니다. 폰에서 쓰려면 HTTPS로 호스팅해야 합니다(예: GitHub Pages). HTTPS가 아니면 "카메라 앱으로 찍기 / 사진 선택" 버튼으로 대신할 수 있습니다.

홈 화면에 앱처럼 설치: 안드로이드 Chrome은 메뉴의 "앱 설치", iOS Safari는 공유 → "홈 화면에 추가". 한 번 열어 모델을 받아 두면 이후 오프라인에서도 동작합니다(첫 실행에는 인터넷이 필요).

## 배포 (GitHub Pages)

`.github/workflows/pages.yml`이 단위 테스트를 돌린 뒤 `build-site.sh`로 만든 정적 사이트(테스트 파일 제외)를 Pages에 올립니다. 배포 job은 **저장소의 기본 브랜치에서만** 실행됩니다(`workflow_dispatch`로 수동 실행도 가능).

한 번만 해야 하는 설정:

1. 이 워크플로가 **기본 브랜치에 들어가 있어야** 합니다 (PR 머지 등).
2. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Actions 탭에서 워크플로가 성공하면 주소가 `https://<계정>.github.io/<저장소>/` 형태로 나옵니다. 앱은 모두 상대 경로라서 하위 경로에서도 동작합니다(로컬에서 하위 경로 아래로 검증함).

주의: **Pages 사이트는 저장소가 비공개여도 인터넷에 공개됩니다**(일반적으로 알려진 동작이며, 공식 문서는 이 환경에서 직접 확인하지 못했으니 **확인 필요**). 또한 비공개 저장소에서 Pages를 쓰려면 유료 플랜이 필요한 것으로 알고 있으나 역시 **확인 필요**입니다. 모델 파일은 저장소에 포함하지 않았지만(라이선스 미확인), 앱이 첫 실행 때 `storage.googleapis.com`에서 직접 내려받으므로 방문자의 IP가 Google 서버에 보입니다. 사진은 업로드되지 않습니다. 자세한 내용은 `vendor/README.md`를 보세요.

배포 후 확인: `curl -sI https://<주소>/vendor/mediapipe/wasm/vision_wasm_internal.wasm | grep -i content-type` 가 `application/wasm`이어야 합니다.

## 구조

| 파일 | 역할 |
|---|---|
| `app.js` | 화면 전환, 길게 누르기, 드래그, 보관함 이동, 낙하 루프 |
| `segment.js` | 누끼: MediaPipe Interactive Segmenter + 예비(배경 제거) 알고리즘, 컷아웃 생성 |
| `physics.js` | 낙하·터치 판정·크기 계산 (DOM 없는 순수 함수) |
| `store.js` | IndexedDB 저장 |
| `sw.js`, `manifest.webmanifest` | 설치·오프라인 |
| `vendor/` | MediaPipe 번들·wasm (`vendor/README.md` 참고). **AI 모델은 번들하지 않고** 첫 실행 때 Google 서버에서 받아 캐시합니다. |

누끼 방식: 누른 지점을 키포인트로 AI 모델(`magic_touch`)에 넘겨 그 물체의 마스크를 얻고, 마스크 영역만 잘라 PNG로 저장합니다. 모델을 못 불러오는 기기(WASM SIMD 미지원 등)에서는 테두리 색을 배경으로 보고 빼는 **간이 모드**로 자동 전환됩니다. 간이 모드는 책상 위 물건처럼 배경이 단순할 때만 쓸 만합니다.

## 테스트

```
node tests/run.js                                   # 물리·판정·간이 누끼 단위 테스트
python3 -m http.server 8080 &                       # 브라우저 테스트용 서버
NODE_PATH=$(npm root -g) node tests/e2e.cjs [스크린샷폴더]   # Playwright + Chromium
```

`BASE_URL=<주소> node tests/offline.cjs`는 첫 접속 후 네트워크를 끊어도 앱과 AI 모델이 동작하는지(서비스 워커 캐시) 확인합니다.

`e2e.cjs`는 가짜 카메라로 촬영 → 사진 로드 → 1초 누르기 → 끌어서 탭 전환 → 낙하 → 새로고침 후 복원 → 겹침/맨 앞으로 → 삭제까지 확인합니다. 테스트용 고양이 사진은 라이선스를 확인하지 못해 저장소에 넣지 않았고, 없으면 MediaPipe 공개 샘플에서 내려받습니다.

## 알려진 한계

- **속도:** 이 개발 환경(GPU 없는 소프트웨어 렌더링)에서는 누끼에 약 6초가 걸렸습니다. 실제 폰에서의 속도는 **확인 필요**합니다. 처음 한 번은 wasm(약 9MB)과 모델(약 6MB)을 내려받는 시간도 듭니다.
- **정확도:** 모델이 한 번에 한 물체의 윤곽을 따며, 복잡하거나 겹친 물체는 틀릴 수 있습니다. 틀리면 다시 길게 눌러 새로 따세요(이전 스티커는 교체됩니다).
- **스토어 앱이 아님:** 지금은 설치형 웹앱(PWA)입니다. 앱스토어/플레이스토어 배포는 별도 래핑(Capacitor 등)이 필요합니다.
- **보관함은 바닥에만 쌓입니다.** 물건끼리 충돌하거나 위에 올라타지는 않고 겹치기만 합니다.
- iOS Safari의 카메라·PWA 동작은 이 환경에서 **직접 검증하지 못했습니다.**
